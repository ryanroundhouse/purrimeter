# Publish Android inside the shared game release through Google Play

The Android build is a fourth package of the one signed game release alongside macOS, Windows and browser play, built and submitted by the same deployment command. Google Play hosts and distributes it, so the release manifest records the bundle's digest and listing URL rather than a downloadable file, and Play's review delays installation by hours or days after the server designates the release. Android players therefore cannot join multiplayer during that window; they keep single player and see a notice pointing at Play. We accept this gap to keep the server-designated admission policy of [ADR 0009](0009-server-designated-release-admission.md) and the single release identity of [ADR 0012](0012-browser-shares-game-release.md) unchanged, instead of adding a per-platform grace period or an independent Android cadence. If the gap proves painful, a bounded admission grace for the immediately preceding release is the intended follow-up.

The Play upload happens before the VM transaction because Play cannot be rolled back or downgraded: a rejected bundle aborts the release with nothing public changed, and a rerun reuses the already-accepted bundle. Version codes derive from the version number (MAJOR×1,000,000 + MINOR×10,000 + PATCH×100) so they stay readable in Play Console and monotonic with the existing rule that a version is never reused for different source.
